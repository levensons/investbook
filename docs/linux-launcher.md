# Linux: один раз настроить, дальше запускать одной командой

Для обычного использования:

```bash
./run.sh
```

Откроется Investbook. Терминал можно закрыть: приложение работает в пользовательской службе Linux. Повторная команда открывает уже запущенное приложение. В меню приложений также появляется значок **Investbook**. После выхода из сеанса пользователя служба может остановиться; автозапуск при входе не включается.

## Первый запуск

Нужны **Linux с пользовательским systemd**, **Python 3.12+** и `xdg-open` для открытия браузера. **Java 26 скрипт установит сам**, если подходящая JDK ещё не найдена. Используйте обычный сеанс своего пользователя, **без `sudo`**. На Linux без systemd остаётся прежний portable `start.sh`; новый launcher для такого окружения не предназначен.

Скрипты находятся в исходниках `levensons/investbook`. Храните исходники отдельно от папки с портфелем, например в `~/src/investbook`. Если репозиторий ещё не скачан:

```bash
mkdir -p ~/src
git clone --branch develop https://github.com/levensons/investbook.git ~/src/investbook
cd ~/src/investbook
```

1. Завершите прежний Investbook кнопкой завершения **в самом приложении**. Закрытие вкладки браузера не останавливает программу.
2. В папке исходников выполните:

   ```bash
   ./setup.sh
   ```

3. Скрипт спросит папку существующей базы. Для стандартной Linux-установки это `~/investbook`; внутри должен находиться файл `investbook3.mv.db`. Подтвердите путь либо укажите свой.
4. Дождитесь окончания сборки. Затем:

   ```bash
   ./run.sh
   ```

Maven загружается wrapper-ом проекта; на первом этапе необходим интернет и `curl` или `wget`. Сборка выполняется при подготовке или явном обновлении, а не при ежедневном запуске. На Linux x86_64 и ARM64 скрипт скачивает JDK 26 Eclipse Temurin с официального сервиса Adoptium, проверяет SHA-256 и устанавливает её в `~/.local/share/investbook-launcher/jdk-26` (либо каталог `XDG_DATA_HOME`). Для первой загрузки нужен доступ к `api.adoptium.net`, GitHub и серверу загрузки GitHub. Установка не требует `sudo`, не меняет системную Java или настройки терминала.

Подходящая JDK 26 из `JAVA_HOME`, уже установленная скриптом Java или JDK в `PATH` используются без повторной загрузки. Проверяются и `java`, и компилятор `javac`. Java 21 и неправильный `JAVA_HOME` не мешают автоматической установке. Выбранная Java используется и Maven при сборке, и службой при запуске; экспортировать `JAVA_HOME` вручную не нужно. Остальные системные зависимости скрипт проверяет, но сам не устанавливает. Для ручного выбора JDK 26 можно по-прежнему задать `JAVA_HOME` перед `./setup.sh`.

**Существующая база остаётся на месте.** Перед установкой и обновлением скрипт сохраняет её копию в `launcher-backups` рядом с базой. Если база открыта другим процессом или порт 2030 занят, подготовка останавливается. Если указанная существующая база исчезла, запуск выдаёт ошибку, а не создаёт пустой портфель.

При нестандартной установке можно явно передать параметры:

```bash
./setup.sh --data-dir /полный/путь/к/папке/базы \
  --config /полный/путь/application.properties \
  --extensions-dir /полный/путь/extensions
```

`--config` сохраняет дополнительные настройки прежней установки, например параметры почты и пароль БД; файл остаётся на прежнем месте. Путь к базе, порт 2030, локальная привязка, путь к журналам и настройки MCP задаются launcher-ом. Если раньше ставили расширения брокеров, обязательно укажите их каталог через `--extensions-dir` (у пакетной Linux-установки обычно `/opt/investbook/lib/app/extensions`). Скрипт не переносит и не удаляет расширения или настройки старой установки.

Поддерживается стандартная файловая H2-база `investbook3.mv.db`. Docker, MariaDB и другая схема хранения требуют отдельного переноса: не направляйте этот launcher на них как на обычную H2-папку.

Только для намеренно нового пустого портфеля:

```bash
./setup.sh --data-dir "$HOME/investbook-new" --new
```

При наличии готового исполняемого JAR из этой версии исходников можно пропустить сборку: `./setup.sh --jar /полный/путь/investbook.jar`. Java всё равно нужна. `--no-desktop` пропускает создание значка в меню.

## Остановка, состояние и обновление

```bash
./run.sh status    # состояние приложения и процесса туннеля, папка журналов
./run.sh stop      # остановить приложение и туннель
./run.sh restart   # перезапустить и открыть браузер
```

Для запуска без открытия браузера: `./run.sh start --no-browser`.

Обновление выполняется явно из папки исходников:

```bash
./run.sh stop
git pull --ff-only
./setup.sh --update
./run.sh
```

Обновление сохраняет выбранную базу, дополнительные настройки, расширения и настройку MCP. Если MCP настроен, его зависимости также обновляются через сохранённый `uv.lock`. Не перемещайте папку исходников с настроенным MCP: профиль туннеля ссылается на её Python-окружение. Обычный `run.sh` не выполняет Git, Maven, установку пакетов или обновление схемы сам по себе; миграции БД выполняет приложение при старте новой версии, как и при обычном обновлении Investbook. Поэтому резервная копия создаётся до первого запуска обновлённого JAR.

## Подключение к ChatGPT — отдельно, один раз

Investbook можно использовать сразу, не настраивая ChatGPT.

Для MCP дополнительно нужны:

- `uv` — [установка](https://docs.astral.sh/uv/getting-started/installation/);
- `tunnel-client` — [официальная Linux-версия](https://github.com/openai/tunnel-client/releases/latest), доступная в `PATH`;
- `secret-tool` и работающая связка ключей рабочего стола (Debian/Ubuntu: пакет `libsecret-tools`).

В [настройках OpenAI](https://platform.openai.com/settings/organization/tunnels) создайте туннель, связанный с нужным рабочим пространством ChatGPT, и получите runtime API key. Для создания нужны права Tunnels Read + Manage, для использования — Read + Use; право добавлять custom MCP в ChatGPT проверяется отдельно. [Официальная инструкция](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

Далее на ноутбуке:

```bash
./run.sh stop
./setup.sh --mcp
./run.sh
```

Мастер спросит ID туннеля, псевдонимы и реальные ID разрешённых счетов, затем ключ OpenAI (ввод скрыт). Номера счетов сохраняются только в закрытых локальных настройках. Ключ хранится в связке ключей Linux, не в исходниках и не в аргументах команд. Локальный токен Java/MCP генерируется при каждом запуске и автоматически передаётся обоим процессам — вручную экспортировать его не нужно.

В [ChatGPT Plugins](https://chatgpt.com/plugins) добавьте **custom MCP server**, выберите **Connection: Tunnel** и тот же туннель. После создания попросите показать доступные счета. Только успешный ответ подтверждает подключение: статус «процесс туннеля запущен» сам по себе этого не гарантирует.

Ноутбук и приложение должны работать во время запросов. Если ключи заблокированы, туннель не установлен или завершился с ошибкой, Investbook продолжит работать. После устранения причины выполните `./run.sh restart`. Автоматическое создание туннеля в аккаунте OpenAI и выдача прав в ChatGPT не выполняются.

## Где находятся настройки

Стандартные пути (учитываются `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME`):

- `~/.config/investbook-launcher/` — закрытые настройки, расположение существующей базы, псевдонимы счетов;
- `~/.local/share/investbook-launcher/` — готовый JAR и служебный скрипт;
- `~/.local/state/investbook-launcher/` — журналы приложения и туннеля;
- `~/.config/systemd/user/investbook-launcher.service` — служба;
- `~/.local/share/applications/investbook-launcher.desktop` — значок приложения.

Настройки и журналы не нужно присылать в чат целиком: они могут содержать информацию о портфеле. Для диагностики ошибки службы используйте `systemctl --user status investbook-launcher.service`. При запуске через значок ошибка также показывается уведомлением рабочего стола, если установлен `notify-send`.

## Проверки для разработчика

```bash
python3 -m unittest discover -s tests/launcher -v
bash mvnw --batch-mode -DskipTests -Dno-installer -Dno-zip package
python3 tests/launcher/smoke.py target/investbook-2026.1.jar
```

Для smoke-теста нужен свободный порт 2030, JDK 26, `systemd-analyze` и `desktop-file-validate`. Он запускает настоящий JAR и временную H2-базу, проверяет перезапуск, локальную MCP-авторизацию, смену токена, отказ тестового туннеля и остановку дочерних процессов. Системная регистрация службы подменяется: CI-контейнер не содержит пользовательского сеанса systemd. Синтаксис службы и ярлыка проверяют штатные утилиты; работа меню и настоящего OpenAI-туннеля требует проверки на ноутбуке.
