# Ограничения первой версии

- Реализованы локальные инструменты чтения. Подключение к пользовательскому ChatGPT и личному портфелю ещё не выполнялось. Наличие документации Secure MCP Tunnel не подтверждает права конкретного аккаунта.
- `get_performance` сообщает изменение оценки и записанные денежные потоки. Денежная прибыль, точный TWR, XIRR всего портфеля и атрибуция не реализованы. См. [контракт](contract.md).
- Полнота импортов не выводится из последней даты операции. При отсутствии брокерского снимка количества предполагают полную историю сделок; возможные начальные остатки и пропущенные корпоративные действия требуют сверки.
- Брокерские снимки позиций и денег трактуются как полные для счёта в их момент времени, как в существующей модели Investbook. Если брокер присылает отдельные рынки в разные моменты, необходима отдельная проверка полноты снимка. Пустой снимок позиций не представлен строками и неотличим от отсутствующего.
- Движения денег после последнего денежного снимка не реконструируются. При таких операциях итог портфеля `null`; нужно загрузить свежий отчёт. Старый снимок без более поздних записанных операций может использоваться с предупреждением о давности.
- Деривативы и валютные пары не оцениваются как обычные бумаги. Для облигаций нужна абсолютная цена; процентная котировка не заменяет её. В первой версии нет резервной оценки всего счёта по итогу брокера.
- Отсутствующий FX или котировка не заменяются нулём. Устаревшие сохранённые оценки явно отмечаются; API не запрашивает котировки в интернете.
- Суммирование подписанных денежных потоков не распознаёт пары переводов через разные даты/валюты и переводы бумаг. Поэтому разность стоимости за вычетом пополнений не названа прибылью.
- Offset-пагинация стабильна при неизменной БД; импорт/редактирование между страницами требует нового прохода. Для больших историй нужно сузить период/счета.
- Ограничения API защищают его собственные запросы. Старые HTTP-маршруты Investbook сохраняют существующий `permitAll`; весь веб-сервер нельзя выставлять в интернет. Публикуется только MCP через отдельно настроенный частный канал, сервер приложения слушает loopback.
- Проверено на Linux, Java 26, Python 3.12, H2. MariaDB и пользовательские Windows/macOS-инсталляции в этой задаче не запускались. Транспорта MCP HTTP и публичного OAuth-сервиса в MVP нет.
