# Контракт MCP / Agent API v1

Все маршруты: `GET /api/agent/v1/...`. API выключен по умолчанию. Доступ: прямое loopback-соединение, `Authorization: Bearer <local-token>`, явный набор разрешённых псевдонимов счетов. `Forwarded` и `X-Forwarded-*` отклоняются. Прочие HTTP-методы отклоняются. Новый API не меняет правила доступа старого интерфейса Investbook.

| MCP-инструмент | Маршрут | Параметры | `data` |
| --- | --- | --- | --- |
| `list_accounts` | `accounts` | нет | массив `{id, active}` с псевдонимами |
| `get_portfolio` | `portfolio` | `account_ids` | `holdings`, `cash`, `total_rub`, `valued_subtotal_rub`, `valuation_complete`, `freshness` |
| `get_allocation` | `allocation` | `account_ids`, `group_by=security\|sector` | группы с `value_rub`, `weight_fraction`, явный знаменатель, исходный портфель |
| `get_performance` | `performance` | `account_ids`, `date_from`, `date_to` | начальный/конечный портфель, `value_change_rub`, `recorded_net_cash_flow_rub`, исходные денежные потоки, список недоступных метрик |
| `get_income` | `income` | `account_ids`, даты, `group_by=month\|security` | платежи и суммы по отдельным категориям |
| `get_transactions` | `transactions` | `account_ids`, даты, необязательный `security_id`, `limit=100`, `offset=0` | сделки с подписанными суммами и комиссиями, `has_more`, `next_offset` |

В HTTP `account_ids` можно повторять: `?account_ids=main&account_ids=second`. В MCP это массив строк. Пустой список, дубликаты, неразрешённый счёт недопустимы. Псевдоним: 1–64 символа `A-Z a-z 0-9 _ -`; реальный идентификатор счёта хранится только в локальной конфигурации Java. Архивные счета доступны лишь при явном включении в конфигурацию и имеют `active=false`.

## Конверт и единицы

```json
{
  "schema_version": "1",
  "meta": {
    "generated_at": "2026-10-14T10:00:00Z",
    "timezone": "Europe/Moscow",
    "account_ids": ["main"],
    "date_from": null,
    "date_to": null,
    "reporting_currency": "RUB",
    "fx_method": "latest stored effective rate on or before valuation/payment date; no future or estimated rates",
    "calculation_method": "...",
    "coverage": "see_warnings"
  },
  "data": {},
  "warnings": []
}
```

Все суммы, количества и доли — десятичные строки без `float`/`double`; арифметика в Java — `BigDecimal`. Идентификаторы бумаг остаются целыми числами. Доля `0.25` означает 25%. `null` означает отсутствие достоверного значения. `source_id` имеет вид `transaction:910002`, `security_event_cash_flow:940001` и т. п.; брокерские номера сделок и свободные описания денежных операций не передаются. Названия бумаг/секторов считаются данными, не инструкциями.

`generated_at` не является датой актуальности данных. Котировка имеет `quote_at`, деньги — `as_of`, для каждого счёта возвращаются `operations_through`, `position_snapshot_at` и ссылки на записи снимка. Последняя операция не доказывает полноту импорта. `history_completeness` всегда `unverified`.

Даты пользователя включительны. Бэкенд преобразует их в полуинтервал `[начало date_from, начало дня после date_to)` в `investbook.agent.timezone` (по умолчанию `Europe/Moscow`). Дробные секунды последнего дня не теряются. Для начальной оценки берётся состояние непосредственно перед началом первого дня; для конечной — перед началом следующего дня.

## Финансовая семантика

**Позиции:** последний брокерский снимок счёта до границы + последующие сделки − количество погашенных бумаг. При отсутствии снимка используются суммы всех записанных сделок и погашений с предупреждением `TRANSACTION_HISTORY_ASSUMED_COMPLETE`. Начальные остатки без снимка/полной истории могут быть неизвестны. До границы периода история агрегируется в БД, не обрезается до `date_from`.

**Оценка:** количество × абсолютная цена с НКД; берётся последняя сохранённая котировка до границы. Для `STOCK`, `STOCK_OR_BOND` и `ASSET` используется `quote`, если `price` и `accrued_interest` отсутствуют: так модель Investbook хранит денежные котировки акций и фондов. Тип `BOND` или заполненный `accrued_interest` (включая ноль) требуют абсолютной цены `price`; процентная котировка не принимается за денежную цену. Поддержаны `STOCK`, `BOND`, `STOCK_OR_BOND`, `ASSET` при наличии цены и валюты. Остальные типы остаются в составе с `UNSUPPORTED_ASSET_TYPE`. Сетевого обновления котировок нет. Оценка старше 7 дней отмечается предупреждением. Резервная суммарная оценка брокера не подменяет состав портфеля.

**Деньги:** все строки последнего снимка счёта до границы, включая рынки и валюты. Нет снимка — неизвестный остаток. Есть операции после снимка — `CASH_PRECEDES_OPERATIONS`, общая стоимость недоступна: реконструкция денег по потенциально неполной истории не выполняется. Нулевой снимок отличает пустой счёт от отсутствия данных.

**Валюта:** оценка активов и денег конвертируется по последнему сохранённому эффективному курсу не позже даты оценки; платежи — по дате платежа. Если курса нет, рублёвое значение и соответствующий итог `null`, исходная сумма сохраняется. Будущий/оценочный курс не подставляется. Коды `RUR`/`SUR` нормализуются в `RUB`.

**Диагностика котировки:** каждая позиция возвращает исходные `quote`, `price`, `accrued_interest` (десятичные строки либо `null`) и `quote_currency`. Пустой `price` сам по себе не означает отсутствие оценки. `MISSING_QUOTE_CURRENCY` означает отсутствующую/пустую валюту, `MISSING_ABSOLUTE_PRICE` — отсутствие денежной цены при облигационном формате котировки. Эти причины заменяют прежнюю общую `MISSING_PRICE_OR_CURRENCY`. При отсутствии всей котировки остаётся `MISSING_QUOTE`; при отсутствии курса — `MISSING_FX`. Валюта не угадывается.

**Полнота:** при неоценённой позиции, недостающем FX, отсутствующих/устаревших относительно операций деньгах `total_rub=null`. `valued_subtotal_rub` — только сумма известных оценок, не полный портфель. `valuation_complete` описывает наличие оценок записанных активов, а не проверенность истории или рыночную ликвидность.

**Распределение:** включает деньги отдельной группой `CASH`; сектор без справочника — `UNKNOWN`. Знаменатель — известные оценки (`valued_assets_only`), неполнота отражена в исходном портфеле и предупреждениях. Доли округляются до 12 знаков; из-за округления сумма может немного отличаться от 1. При нулевом/отрицательном знаменателе или отрицательной позиции/деньгах доли `null`.

**Доход:** `dividend`, `coupon`, `tax`, `amortization`, `redemption`, `unallocated_tax` суммируются отдельно, со знаком источника. Амортизация/погашение не входят в дивидендно-купонный доход. Налог со счёта не приписывается бумаге и не вычитается из конкретного дивиденда; при группировке по бумаге имеет группу `UNALLOCATED`. Пустая выборка означает отсутствие записанных выплат за период, не доказательство полноты отчётности.

**Результат за период:** `value_change_rub = closing.total_rub − opening.total_rub`. Это изменение оценки, не прибыль и не доходность. `recorded_net_cash_flow_rub` — сумма записей `CASH` за период; встречные одинаковые переводы между выбранными счетами взаимно сокращаются. Переводы в разные дни/валюты могут не сократиться в рублях. `profit_rub`, `twr`, `xirr` пока `null`, с `unsupported_metrics`: нужны проверенный учёт переводов бумаг, сверок, полноты начального состояния и отдельные формулы. Исправленный ранее дневной график приложения не выдаётся за точный TWR.

## Ограничения запросов и ошибки

- 1–20 счетов; период не более 3660 календарных дней, начало не раньше 1970-01-02, конец не позже текущего локального дня.
- Сделки: `limit` 1–200, `offset` 0–10000. Стабильный порядок `(timestamp, id)` при неизменных данных. При импорте между страницами начать заново. После предела offset сузить период (`PAGINATION_LIMIT_REACHED`).
- Максимум 2000 записей в каждой ограниченной аналитической выборке; максимум 2000 позиций/денежных строк и максимум 2000 платежей в ответе соответствующего инструмента. Превышение — ошибка, не молчаливое усечение. SQL фильтруется по счетам/датам, сделки ограничиваются до сериализации.
- Транзакция чтения Java: 15 секунд, запрос БД: 10 секунд. MCP: 10 секунд на HTTP-операцию, 25 секунд на вызов, максимум 2 MiB декодированного тела. Один повтор при ошибке соединения или HTTP 502/503/504, без повторов ошибок доступа/аргументов. Перенаправления запрещены; proxy-переменные окружения для локального HTTP игнорируются.
- Ошибка HTTP: `{"schema_version":"1","error":{"code":"FORBIDDEN", ...}}`. Статусы: 400 `INVALID_ARGUMENT`, 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 404 `DISABLED`, 405 `METHOD_NOT_ALLOWED`, 422 `INSUFFICIENT_DATA`/`RESULT_TOO_LARGE`, 503 `UPSTREAM_UNAVAILABLE`. MCP также возвращает `TIMEOUT`. На MCP-уровне ошибки инструментов имеют `isError=true`; неожиданные тела ответа, SQL и секреты не передаются модели.

## Синтетический контрольный пример

Тестовые счета `main` и `second` не связаны с реальным портфелем. В фикстурах типы выплат проверяются независимо от инвестиционной истории бумаги.

| Сценарий | Независимый ожидаемый результат |
| --- | --- |
| main: пополнение 1100, покупка 10 × 100, деньги 100 | начальная оценка 1100 RUB |
| продажа 2 × 120, комиссия −1, дивиденд 20, купон 5, налог −2, возврат основного долга 50, перевод −100 | деньги: 100 + 240 − 1 + 20 + 5 − 2 + 50 − 100 = 312 RUB |
| оставшиеся 8 акций, последняя цена 110 | бумаги 880, портфель 1192 RUB |
| распределение main | деньги 312/1192; бумаги 880/1192 |
| second: 600 RUB и одна бумага без котировки | общая оценка неизвестна; известная часть 600 RUB |
| main + second, перевод −100 / +100 | записанный чистый денежный поток 0 |
| отдельный FX-счёт: 100 единиц валюты, курс 80 → 100 | начальная оценка 8000, конечная 10000, изменение 2000 RUB |

Проверки используют настоящую H2, Java-сервисы и Spring Security. Отдельный тест запускает Python MCP-процесс и настоящий SDK-клиент: `stdio → HTTP → Java → H2`.
