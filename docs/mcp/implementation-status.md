# Статус реализации MCP

Дата: 2026-10-14. Исходный SHA: `8e17cd758a9b7f7da5d7bdc31b1bc4b74c8def1b` (`develop`). Рабочая ветка: `feature/investbook-mcp`.

Перед началом MCP в рабочей копии уже были согласованные исправления исторического FX, дневного роста и XIRR с 22 регрессионными тестами. Они сохранены. Базовый полный прогон после этих исправлений: 200 тестов, 193 прошли, 7 ранее отключены. MCP не использует глобальный `ViewFilter` и не выдаёт дневной график за точный TWR.

Стек: Java 26 / Spring Boot 4.1 / JPA / существующая БД; отдельный Python 3.12+ пакет, официальный `mcp==2.3.0` (`MCPServer`), HTTPX 0.28.1, `stdio`. Версии и хеши Python-зависимостей сохранены в `uv.lock`. Новые таблицы и миграции не нужны.

Локальная разработка и тесты выполняются на синтетической H2-базе. Чтение настоящего портфеля, создание туннеля и его runtime-ключа, публикация сервиса, push/PR не выполнялись.

## Итог проверок

- `INVESTBOOK_MCP_PYTHON=... bash mvnw clean test`: 222 теста, 215 прошли, 7 ранее отключены; ошибок и падений нет. Включены генерация исходников, проверка nullness, HTML-документация и JaCoCo.
- В MCP-части 22 новых Java-теста: 19 API/финансовых, 2 конфигурации и безопасности по умолчанию, 1 сквозной MCP-тест.
- `uv run --frozen --project integrations/investbook-mcp pytest integrations/investbook-mcp/tests -q`: 25 прошли.
- Настоящий Python SDK-клиент через отдельный stdio-процесс успешно вызвал все 6 инструментов у Java/H2 и получил MCP-ошибку при запросе запрещённого счёта.
- `git diff --check`: без замечаний.
- После полного прогона обычный dev-сервер перезапущен: health, главная страница и статистика счетов отвечают HTTP 200; новый API без включения отвечает HTTP 404 / `DISABLED`.
